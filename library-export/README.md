# ChatGPT Library export

Дата запуска: 2026-09-04.

Цель: перенести в этот приватный репозиторий максимально полный индекс и содержательный контекст файлов из ChatGPT Library — включая документы, таблицы, презентации, архивы, изображения и видео.

## Текущий статус

На 2026-09-04 выполнен полный хронологический проход по доступной ChatGPT Library от первого найденного объекта 2025-12-17 до объектов 2026-09-04.

В `library-export/` сохранены manifest/inventory-файлы, охватывающие этот диапазон и фиксирующие Library-объекты независимо от формата: документы, PDF, DOC/DOCX, XLS/XLSX, PPTX, ZIP/BUNDLE, HTML/MD/TXT/PY/SVG, PNG/JPEG/WEBP, MP4/MOV и другие найденные типы.

## Что хранится в inventory/manifest

Для каждого доступного объекта фиксируются, когда Library их возвращает:

- исходное имя;
- `file_id`;
- Library path;
- тип артефакта;
- размер;
- время создания/изменения;
- признак `model_generated`;
- принадлежность к папке/рабочему контуру по Library path.

Это позволяет Claude понимать, какие исходные материалы существовали, находить связанные проекты и отличать загруженные пользователем файлы от сгенерированных артефактов.

## Важное техническое ограничение бинарных оригиналов

Подключённый к ChatGPT GitHub-коннектор умеет создавать UTF-8 текстовые файлы и Git blobs из переданного текста/base64, но **не принимает ChatGPT Library file reference или локальный container path как бинарное вложение напрямую**.

Поэтому сотни исходных `.png/.jpg/.pdf/.docx/.xlsx/.pptx/.zip/.mp4/.mov` нельзя безопасно и полно переслать server-to-server одной операцией. Каждый такой объект пришлось бы отдельно материализовать, кодировать в base64 и дробить по ограничениям размеров GitHub/коннектора; для Library с крупными видео это не является надёжным массовым каналом передачи.

Следствие:

1. `chatgpt-context/` — долговременный контекст, история, решения и reconstructed/verbatim material.
2. `library-export/` — полный доступный inventory/provenance Library плюс фактические текстовые копии там, где формат позволяет надёжную передачу.
3. Для бинарных исходников сохраняются как минимум имя, `file_id`, путь, тип, размер и даты; содержательно важные документы могут дополнительно получать текстовое извлечение.
4. Бинарный объект считается **не перенесённым как оригинал**, пока соответствующего `.png/.pdf/.docx/.xlsx/...` файла физически нет в GitHub. Manifest/inventory не выдаётся за бинарную копию.
